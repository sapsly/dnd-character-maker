Heading

A deliberately long subtitle paragraph that keeps going and going so it has to wrap over several lines inside whatever width this header block decides to give it, which is the whole point of the test: if it wraps narrow while the header is wide, that is the bug.

A card title that is really a whole long sentence describing the section in detail so it has to wrap

Card body paragraph. This is the standard body copy slot that hosts most of the app's prose: feature rules, spell text, inventory notes. When the paragraph runs long it should still fill the card's full inner width instead of hugging one side and leaving dead space beside it. Anything else is a layout bug.

Label

A field hint long enough to wrap: the hint should span the field's full width, not stop halfway across and leave a hole to its right.

Panel title

Panel paragraph. Same test, plain container: long prose must occupy the panel's whole content width, wrapping across as many lines as it needs, with no reserved empty lane on either side of the text block.

Empty state

Empty state description long enough to wrap several times, testing whether the capped measure here is centered inside the card or thrown to one side with a lopsided gap.

Modal title

Modal description paragraph that runs long on purpose, because modal descriptions are exactly where the app puts explanatory prose, and it must fill the modal's width evenly.

Modal body paragraph. Same contract: wrap at the modal's inner width, fill it, leave no empty lane beside the text.
